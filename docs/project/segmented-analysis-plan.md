## 1. 目标与交付批次

传入一份完整 DataFrame，在原有业务分组或时间粒度之外增加独立的客群列。一次分析同时提供 All 整体及各客群的结果，例如 All、seg1、seg2、seg3 分别在 Train／Val／Test 或各月份的分布、质量和风险表现。

项目定位继续为：**面向人和 AI Agent 的高性能信贷风控工具箱**。客群信息需要进入结构化结果、原生图、交付文件和证据引用，人工和 Agent 使用同一份统计。

| 批次 | 覆盖范围 | 完成条件 |
| --- | --- | --- |
| 第一批，优先 | 风险画像、数据画像、统计特征筛选、报告全链路 | 共享／独立分箱、独立筛选、查询、原生图、HTML／Excel、保存恢复全部贯通 |
| 第二批 | 模型分交叉 | 保留现有分组与独立时间轴，新增客群、按客群固定分段及策略回放 |
| 第三批 | 规则评估、缺失异常诊断 | 固定规则和缺失异常均可按客群与原切片分析，保持各自的统计语义 |

允许按下文里程碑拆分提交和 PR；第一批验收后再推进第二、三批。每一批都交付可用的完整链路，不只添加签名或演示图。

本计划不扩展通用多维 Cube、自动发现客群、客群模型训练或通用 Agent 调度平台。每次调用先支持一个 `segment_col`。Linear／Importance Selector 的独立客群筛选暂不纳入此次实现。

Monitoring、Modeling（包括 Pipeline）、Scoring 暂停新功能迭代，只做本次上游变化所需的直接适配。上游不为这三个模块保留旧字段、转发壳或双轨计算；核心公共 API 与已保存报告仍需评估兼容性。

## 3. 统一参数与默认行为

### 3.1 参数职责

| 参数 | 位置与取值 | 职责 |
| --- | --- | --- |
| `segment_col` | 分析／评估／扫描的运行方法，以及 StatsSelector 的 `fit()`；默认 `None` | 指定当前输入中的客群列 |
| `binning_scope` | 有分箱拟合职责的入口；`"shared"` 或 `"per_segment"`，默认 `"shared"` | 决定规则在整体还是各客群拟合 |
| `selection_scope` | StatsSelector 构造策略；`"global"` 或 `"per_segment"`，默认 `"global"` | 决定只执行整体筛选，还是同时执行各客群独立筛选 |

构造函数保存稳定策略，运行方法接收数据和本次上下文。`profile_risk()` 等便捷函数显式传递这些参数，避免只在高层接收而底层忽略。

数据画像的 `binning_scope` 用于 PSI 的内部规则拟合；均值、缺失率等统计不受其影响。未请求任何适用指标却传入非默认分箱模式时明确报错，不静默忽略。规则评估和缺失异常诊断不增加无效的 `binning_scope` 或 `selection_scope`。

未传 `segment_col` 时维持现有结果、默认返回、表结构、数值、排序与导出；使用需要客群的非默认模式时入口报错。`segment_col` 自动从默认特征集中排除；不允许同时把它显式声明为待分析特征或目标，也不允许与分组、日期、权重、金额角色重叠。

原有分组行为保持：风险画像和数据画像中，提供 `group_col` 时仍优先按该列组织趋势；`time_col` 继续提供日期信息。新增客群不改变其优先级，也不擅自引入额外时间分组轴。

### 3.2 风险画像的两种分箱模式

| 分析范围 | `shared` 的拟合人口 | `per_segment` 的拟合人口 |
| --- | --- | --- |
| All | 既定整体拟合人口 | 既定整体拟合人口 |
| seg1 | 复用整体规则 | 既定拟合人口中的 seg1 |
| seg2 | 复用整体规则 | 既定拟合人口中的 seg2 |
| seg3 | 复用整体规则 | 既定拟合人口中的 seg3 |

既定拟合人口沿用当前契约：有 `benchmark_df` 时使用该基准；没有时沿用现有入口的拟合规则。不会仅凭 `dataset_flag` 或名称推断 Train，更不会自动改写调用方标签。文档推荐显式传入开发样本作为 benchmark。

同一客群的所有评估分组和月份都使用该客群固定规则，不按月、验证集或不同评估目标重新拟合。`shared` 共享切点、类别定义及拟合所得映射；各客群的质量、表现、金额与稳定性统计仍在各自人口内计算。表内按客群计算的统计 WOE 与 estimator 用于转换的已学 WOE 映射须在目录中说明，不能混用或由生成报告覆盖已学映射。

`MarsRiskProfile.binner` 保留为整体分箱器；新增按客群可取的规则索引及各客群状态。独立规则通过既有正式分箱规则格式及必要索引保存，不使用 pickle。显式传入整体 `binner` 只适用于共享规则；独立模式使用明确的客群规则集合，冲突配置和缺失规则不能静默回退整体或重新拟合。

### 3.3 StatsSelector 的合法组合

| `selection_scope` | `binning_scope` | 行为 |
| --- | --- | --- |
| `global` | `shared` | 保留整体筛选；若传客群列，只登记角色，不自动生成客群筛选或报告 |
| `per_segment` | `shared` | All 与各客群独立筛选，共享各阶段的固定分箱规则 |
| `per_segment` | `per_segment` | All 与各客群分别拟合、分别筛选 |
| `global` | `per_segment` | 入口报错；本期不定义多客群证据合成单一名单的规则 |

`selected_features_` 和默认 `transform()` 始终表示整体结果。新增 `selected_features_by_segment_` 或等价的明确客群结果索引，保存客群原始类型和值，避免字符串键碰撞。独立模式也要保留 All 结果。并集、交集和任一客群通过即保留不自动执行；若用户自行合并，文档说明其业务含义。

## 4. 所有批次共用的业务契约

### 4.1 All、客群与 Total

All 表示未限制客群的完整输入人口；Total 表示某个分析范围内跨全部原分组的汇总。All 单独从原始人口聚合，不能平均客群指标。各客群 Total 也不能平均各月份的 KS、IV、AUC、PSI 或坏率。

新增客群目录表，拟名 `scopes`：保存 `scope_id`、整体／客群类型、客群列、原始 dtype 与编码值、展示名、排序和计算状态。业务事实表以 `scope_id` 连接目录，避免每个箱或每对特征都重复长客群文本。最终字段定义在 P00 冻结。

整体身份不能借用普通字符串或 null。真实客群值 `"All"`、`"Total"`、`"Missing"`、`"null"`、空字符串、null 和数值类别须可区分；不因展示转字符串丢失身份。标量类型复用现有受限编码；不支持的混合对象／嵌套类型在入口拒绝。null／NaN 按既有缺失语义归为缺失客群，字符串 `"NaN"` 不自动归缺失；缺失客群保留，不丢弃其样本，无穷数值客群拒绝。scope ID 依据客群列、类型和值确定，不依赖显示名或样本行顺序，保存恢复后不变。

按实际出现的客群计算，展示顺序稳定并记录。某客群某月不存在样本时，不补造风险为零的统计；展示为无数据，若视图补齐空格子则人数为 0、其余指标按语义为 null，并保留状态。

### 4.2 拟合规则、PSI 与 RC 参考分别记录

- All 的 PSI expected distribution 来自整体 benchmark；seg1 来自 benchmark 的 seg1。分箱模式不改变此人口匹配。
- 按客群匹配基准时，`benchmark_df` 必须有客群列且类型可对应；缺列或歧义类型在入口报错。
- 基准中缺少某客群、没有有效样本或有效权重为零时，记录该项不可计算原因，不使用整体分布代替。
- 无显式 benchmark 时，先依现有分组排序契约选定整体参考组，再将同一组应用于各客群；该客群在参考组没有样本时记录缺参考，不擅自改用自己的下一期。分箱拟合人口与 PSI 参考人口仍分别记录。
- RC 的 `total` 使用当前 scope 的 Total，`benchmark` 使用对应客群基准，`first_group` 使用上文选定的同一整体首组在当前 scope 的样本；缺该组时记录不可计算，不跳到该客群的下一期。实际参考组、日期和人口进入报告。不得把整体坏率／分布意外连接到某个客群。
- 特征上线时间参考保留现有显式 benchmark 优先级；新增客群时按当前 scope 识别和记录日期。样本不足应明确状态，不能直接复用整体上线日。

### 4.3 标签、权重、金额与异常状态

分布、缺失、PSI 使用各 scope 的适用完整人口；标签指标只用该 scope、该 target 的已观察样本。标签仍为合法二分类或缺失，不能将 `-1` 当成未表现直接计算。权重、金额有效性、分母和单位沿用各模块现有定义。

整体输入结构非法、非法标签或非法权重等契约错误应报错。某个客群统计不足则记录局部状态，其他合法客群继续计算。监督拟合只有一个类别、客群为空、算法拟合失败、规则缺失、未计算及成功但统计未定义必须区分；不能填 0／1 或继承上一次运行结果。

不得将失败客群自动切换为无监督算法、整体分箱或另一个目标。保留现有整体无标签入口的合法行为时，报告必须记录实际生效算法。评估期单类别的处理按具体指标定义：可定义的分布／坏率仍计算，不能将所有风险指标统一填值或整个客群无条件报废。

多目标继续遵循当前能力边界：首目标负责拟合，同一 scope 内其他目标复用规则并各自处理未表现人口；当前趋势表只覆盖首目标。此次不顺带改成全部目标自动拥有趋势表。

### 4.4 重复运行与复用

重复 `fit()`、失败后再拟合、不同客群集合和不同特征集合之间，所有客群结果与缓存必须正确重建。不得读到上一次存在、这一次已消失的客群规则。固定规则评估和规则恢复禁止重新拟合；当前未见过的客群不能自动拿整体规则顶替，除非调用方明确选择共享模式。

### P02：风险画像与分箱规则

- [ ] `profile_risk()` 和 `MarsBinEvaluator.evaluate()` 全链路支持 segment；多目标入口、raw KS 和固定 binner 入口不遗漏。
- [ ] 实现 shared／per_segment 两模式；All 独立规则保留，客群规则有明确归属、参数和失败状态。
- [ ] shared 每批尽量只转换一次，按 scope／group／bin 聚合；per_segment 复用底层分箱，按客群有界拟合与评估。
- [ ] PSI、RC、单调性、坏率／金额坏率及其分母在当前 scope 内计算；固定分箱跨时间复用。
- [ ] raw KS、binned KS、summary／trend 替换及所有 join／pivot 键加入 scope 和现有目标、特征、分组身份。raw 结果继续保留；Excel 中最终 KS 使用当前 scope 的既定 binned KS 合同，不跨客群取 max。
- [ ] 各客群及各 group 的日期范围从当前适用人口聚合，不能拿整体日期替代；不依赖字符串组名猜日期。

## 8. 性能与内存要求

客群会增加统计和报告规模，不能承诺增加维度没有成本。结果规模通常随特征 × 客群 × 分组 × 箱数增长；完整相关性还有各 scope 的候选平方项，模型分交叉还涉及两轴格子。

1. 先投影特征批和必要角色列，再转换和物化。shared 模式复用本批分箱结果，All 与客群尽量共享基础聚合；不通过复制一份 All 人口再 concat 所有客群实现多层统计。
2. per_segment 允许独立拟合，但默认顺序或有界调度，不同时常驻多个完整宽表、全部 WOE 表和密集矩阵，不叠加客群外层并行与 `n_jobs=-1`。
3. 每个 scope 完成后释放拟合／计算缓存，保留固定规则、必要小统计表和状态；不缓存原始 benchmark 来方便后续报告生成。
4. 沿用真实 lazy 路径、列批控制和分块相关性。不能为了分客群退回全宽 eager、完整 IPC BytesIO hash、全量 Python 行循环或报告先全转 JSON。
5. 计算、显示、查询预算分开。高基数客群应提前报告规模和要求显式缩小；不能用绘图页长掩盖计算成本，也不能静默跳过客群、减行或减特征。
6. 容量验收测量完整公开调用链中真实对象共存，不仅将每个阶段单独放入新进程；All 与客群报告保存、规则持有和相关性报告均计入实际峰值。
7. 小型规模回归覆盖 1／3／较多客群、均衡／极不均衡人口、列批 1／16／100、线程 1／4、类别 Join、长特征名与多 chunk。普通 CI 不加庞大的完整 benchmark。
8. 独立 benchmark 记录 Python／依赖、CPU／内存、行列、客群数、分组数、标签人口、实际候选漏斗、时间与峰值 RSS。跨实现对照继续验证同一输入身份、实际工作和完整数值语义，线程池枚举顺序不作为资源差异。

不得用抽样、改变阈值、只保留相关性局部块、隐藏失败阶段或要求用户先全宽 rechunk 来获得通过。真实大数据在用户授权和可用环境中运行；未运行就记录为未验证。

| 资源 | 客群数、行列规模和候选漏斗变化 | 全链路可测、有界中间对象、结果不减人口 |

Python 3.8–3.12 与 Pandas 2／3 的实际组合以当前 CI 和 constraints 为准，必须覆盖旧 Polars 1.8.2 及当前现代 Polars 的相关行为。现代 streaming 测试在首次 import 前设置线程数，并输出子进程实际版本，避免 PYTHONPATH 重设后误测旧版。

受影响质量门包括 Ruff、Mypy、public／private docstring、定向回归、基础 CI、文档共享示例与严格 MkDocs。真实浏览器检查客群交互、手机宽度与离线恢复报告；Excel 在可用环境实际打开／刷新／重算。缺失环境、未实测平台和未运行的大规模测试单独列出，不能计为通过。
